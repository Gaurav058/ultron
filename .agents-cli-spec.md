## 01. EXECUTIVE SUMMARY & PROJECT PURPOSE

ULTRON V2 is not a chatbot, a voice assistant clone, a generic telemetry dashboard, or an uncontrolled swarm of AI prompts. It is a persistent, multimodal, mission-oriented **Cognitive Operating System** designed to unify reasoning, knowledge, tool execution, memory, and multi-device continuity (Desktop, iOS, Android) into a single cohesive intelligence layer.

### Core Philosophy
1. **Mission-Centric, Not Chat-Centric:** Transient chats are ephemeral. Missions are living, observable, persistent objects backed by Directed Acyclic Graph (DAG) task trees, evidence ledgers, and human-in-the-loop approval gates.
2. **Strict Separation of Concerns:**
   - **Agent:** *Who* performs the work (Identity, Role, Boundary, Risk Tier).
   - **Skill:** *How* the work is performed (Versioned, composable capability packages).
   - **Tool (MCP):** *What* is accessed (Deterministic, sandboxed I/O with strict JSON schema).
   - **Workflow:** *How* actions are orchestrated across parallel/sequential DAGs.
   - **Model:** *Engine of Thought* (Dynamically routed per step based on latency, cost, and context constraints).
   - **Memory:** *What is Retained* (5-tier governed memory plane; unverified hallucinations are never stored as ground truth).
3. **Zero-Mock & Empirical Reality:** No fake thinking timers, mock telemetry loops, or unverified counters. Every milestone must be validated by the **Reality Checker** before being marked completed.

## 03. TRI-PILLAR RUNTIME SUBSYSTEMS

### A. The Cognitive Kernel
The central orchestration supervisor responsible for:
- Intent classification and complexity evaluation.
- Mission decomposition into deterministic DAG task graphs.
- Dynamic team synthesis (assembling specialist agents and expiring mission-scoped temporary agents).
- Constraint-based model routing (matching cost, latency, context window, and privacy boundaries).
- Enforcing least-privilege tool execution policies and security gates.
- Emitting real-time execution telemetry across the WebSocket event bus.

### B. Hierarchical Agent Fleet
Uncontrolled peer-to-peer agent swarms are strictly prohibited. ULTRON enforces a hierarchical supervisor topology:
```
                      CONDUCTOR (Supervisor)
                                │
                    [ Directed Acyclic Graph ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
    RESEARCHER               BUILDER                 SECURITY
 (Evidence & Truth)    (Code & Artifacts)      (Defensive Posture)
        │                       │                       │
   Worker Pool             Worker Pool             Worker Pool
 [Web, ArXiv, Docs]    [FastAPI, Next, DB]    [CVE, SAST, Audit]
        │                       │                       │
        └───────────────────────┼───────────────────────┘
                                │
                                ▼
                         REALITY CHECKER
             (Objective vs. Output Empirical Validator)
                                │
                                ▼
                         MEMORY CURATOR
               (Promote Verified Truth to L3/L4)
```

#### Core Specialist Agents:
1. **ULTRON Conductor:** Master planner, DAG manager, dependency tracker, and escalation coordinator.
2. **Researcher Agent:** Multi-source query expansion, evidence extraction, citation tracking, and claim extraction.
3. **Architect Agent:** High-level system design, schema definitions, and architectural invariants.
4. **Builder / Coding Agent:** Implementation of backend, frontend, database schemas, and unit test suites.
5. **Security Agent:** Defensive posture, SAST scanning, dependency vulnerability audit, secret scrubbing, and zero-trust policy enforcement.
6. **Reality Checker:** Empirical verification gate. Tests actual execution, verifies citations, checks objective alignment.
7. **Memory Curator:** Governs memory promotion pipeline from raw signal to verified durable facts; prunes and expires stale entries.
8. **Device Agent:** Coordinates connected client status, hardware telemetry, push notifications, and cross-device mission handoff.

## 04. THE MISSION MODEL (LIVING AUTONOMOUS OBJECTS)

Missions replace chats as the atomic unit of work in ULTRON.

### Mission Lifecycle States:
`CREATED` ➔ `PLANNING` ➔ `RUNNING` ➔ `AWAITING_APPROVAL` ➔ `VERIFYING` ➔ `COMPLETED`  
*(Exception states: `PAUSED`, `FAILED`, `CANCELLED`, `ARCHIVED`)*

### Mission Entity Schema:
- **`id`**: UUIDv7 (time-ordered identifier).
- **`title`**: Concise human-readable objective.
- **`objective`**: Full unedited user intent and constraint parameters.
- **`status`**: Current state in the state machine.
- **`priority`**: `P0` (Critical), `P1` (High), `P2` (Medium), `P3` (Low).
- **`tasks`**: Directed Acyclic Graph (DAG) of `MissionTask` nodes with prerequisite dependencies.
- **`agents`**: Array of active specialist agents assigned to this mission.
- **`evidence_ledger`**: Grounded citations, source URLs, execution outputs, and proof artifacts.
- **`approvals`**: Pending or cleared human approval gates.
- **`verification`**: Reality Checker assertion score and validation report.
- **`budget_tracking`**: Token usage, cost incurred, model latency histograms.

## 05. FIVE-TIER MEMORY HIERARCHY

Unchecked hallucination occurs when models dump completions directly into storage. ULTRON segregates memory into 5 distinct tiers:

| Tier | Name | Persistence | Scope | Governance |
| :--- | :--- | :--- | :--- | :--- |
| **L0** | Context Memory | Ephemeral (Token Window) | Current inference cycle | Flushed upon turn completion |
| **L1** | Working Memory | Session / Mission Lifespan | Active mission task scratchpad | Accessible to agents working on active DAG |
| **L2** | Episodic Memory | Persistent (Event Log) | Chronological execution journal | Immutable audit trail: actions taken, errors, user feedback |
| **L3** | Semantic Memory | Persistent (pgvector HNSW) | Synthesized knowledge base | Chunked documentation, codebase ASTs, domain ontologies |
| **L4** | Long-Term Memory | Persistent (Relational + Graph) | Verified facts & invariants | User preferences, credentials/endpoints, verified facts |

### Memory Promotion Pipeline:
```
[ RAW SOURCE ] ──► [ EXTRACTED SIGNAL ] ──► [ ATOMIC CLAIM ] ──► [ REALITY VALIDATION ] ──► [ L4 PERMANENT TRUTH ]
  (Web/Code)        (Regex/LLM Filter)        (Confidence > 0.85)     (Deterministic Test)       (Signed Node)
```

## 06. TOOL & MCP ARCHITECTURE

All external system operations are encapsulated as Model Context Protocol (MCP) compatible tools.

### Enforcement Rules:
1. **Least-Privilege Execution:** Default to read-only access. Write, execute, and network egress require explicit scope grants.
2. **Strict Parameter Validation:** Inbound tool arguments are validated via Pydantic / Zod schemas before reaching the driver.
3. **Automated Secret Scrubbing:** Sensitive keys, JWTs, and passwords are redacted from tool stdout before entering LLM context or logs.
4. **Human-in-the-Loop Risk Gating:**
   - `LOW` (Read-only search, local inspect): Autonomous execution permitted.
   - `MEDIUM` (File writes, local builds): Autonomous within project workspace; audit logged.
   - `HIGH` (Database migrations, network push, email/messaging dispatch): Approval modal triggered.
   - `CRITICAL` (Production deployment, credential alterations, destructive deletes): Strict dual-confirmation required.

## 07. REALITY CHECKER: EMPIRICAL VERIFICATION PROTOCOL

No mission is marked `COMPLETED` simply because a model generated affirmative text.

### Verification Gates:
1. **Objective Match:** Semantic cosine distance comparison between initial prompt requirements and generated deliverables (replan if distance > 0.35).
2. **Code Execution:** Automated sandbox test runner must execute unit and integration test suites; zero exit code required.
3. **Fact & Citation Check:** URLs must be reachability-tested and snippet-matched against primary sources. Unverified claims are downgraded to `UNVERIFIED_OPINION`.
4. **Security Policy Check:** Static analysis (SAST) for hardcoded secrets, injection vectors, or dangerous eval patterns.

## 11. DEFINITION OF DONE (DOD)

A feature or subsystem is NOT done until it meets all of the following:
- [x] **Implemented:** Clean, typed, modular code adhering to the architecture.
- [x] **Integrated:** Fully wired into the UI, WebSocket bus, and backend state (no orphaned stubs).
- [x] **Tested:** Unit test coverage for core domain logic; zero-exit status in sandbox.
- [x] **Verified:** Reality Checker validation gates passed.
- [x] **Documented:** Documented in `.agents-cli-spec.md` and `docs/`.
- [x] **Observable:** Telemetry, tokens, and errors visible in System telemetry.
- [x] **Zero Mock:** No simulated timers, fake loading delays, or ungrounded mock responses in live paths.
- [x] **Zero Leakage:** No API secrets, credentials, or private keys exposed in source, logs, or UI.
